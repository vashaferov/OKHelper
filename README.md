# ok-helper-tui

Кроссплатформенный терминальный помощник для работы с треками и путевыми
точками (`.gpx`, `.plt`, `.wpt`). Умеет:

- переименовывать файлы из «скачанных» имён в формат `ГГГГММДД_Позывной`;
- следить за папкой загрузок и предлагать перенести новые файлы в нужную
  директорию;
- загружать файлы на FTP-сервер;
- проверять имена по правилам, заданным в проекте;
- выполнять транслит кириллицы в латиницу.

Программа работает в терминале: Linux, macOS, Windows.

---

## Возможности

### Транслит

Введите кириллическую фразу в поле «Транслит» и нажмите Enter — результат
появится в журнале. Транслит используется и автоматически, когда сервис
приводит имена файлов к латинице.

### Проверка имён файлов

Для файлов `.gpx` и `.plt` сервис ожидает формат:

```
ГГГГММДД_Позывной
```

Где `Позывной` — только латиница, цифры, `_` и `-`.

Скачанные из интернета файлы обычно выглядят иначе:

```
2026-09-17_11-55_бабушка.gpx
2026-09-23-1803 Безымянный трек.gpx
```

Сервис умеет их распознавать и предлагает корректное имя. Рядом с «плохим»
файлом в дереве появляется кнопка:

- **`[Правка]`** (зелёная) — имя сразу понятно, клик переименует;
- **`[Правка]`** (голубая) — дата найдена, позывной осмысленный, клик
  переименует;
- **`[Правка?]`** (жёлтая) — похоже на заглушку («Безымянный трек» и т.п.),
  клик откроет редактор, чтобы поправить имя вручную.

Для `.wpt` допустимо только имя вида `Waypoints_ГГГГММДД`.

Файлы `<1-4 цифры>m.gpx` (например, `100m.gpx` или `20260917_999m.gpx`)
не проверяются — у них своя структура имени.

Файлы с другими расширениями (`.txt`, `.mp3`, `.jpg` и т.п.) не
проверяются.

### Мониторинг папки загрузок

Если в конфиге включён `watch_downloads = true`, сервис следит за папкой
загрузок. Как только там появляется новый файл — открывается модалка:

- **Enter / Y** — перенести в текущую открытую директорию;
- **N / Esc** — пропустить.

Отложенные файлы остаются в очереди (видно в статус-баре как `загр: N`),
вернуться к ним можно по клавише **F8**.

Временные файлы браузеров (`.crdownload`, `.part`, `.tmp` и т.п.) не
попадают в очередь.

### Отправка на FTP

Для выделенного файла нажмите **F12** или кликните кнопку **`[⇪]`** рядом
с именем. Откроется модалка отправки:

- папка назначения подставляется автоматически (ищется вверх по дереву);
- имя папки должно быть в формате `ГГГГ-ММ-ДД_Место`;
- при необходимости папка создаётся на сервере;
- **Ctrl+T** в поле — транслит введённого.

Отправлять можно только:

- `.plt` — с корректным именем;
- `.wpt` — только `Waypoints_ГГГГММДД`;
- `.gpx` — **только** `<1-4 цифры>m.gpx`. Обычный `ГГГГММДД_Позывной.gpx`
  на сервер не уходит (для FTP это правило строже, чем для локальной
  проверки).

Для остальных файлов кнопка `[⇪]` не показывается, а F12 пишет причину в
журнал.

### Режим эмуляции FTP

Если в конфиге стоит `ftp_readonly = true` — сервис реально подключается,
читает папки, но **не создаёт** их и **не загружает** файлы. В журнал
пишется, что было бы сделано. Удобно для проверки настроек и валидации
без риска.

## Клавиши

### Основное окно

| Клавиша | Действие |
|---|---|
| `F1` | Справка |
| `F2` | Фильтр: все / только ошибки |
| `F3` | Открыть выделенный файл системным приложением |
| `F4` | Сортировка: имя → дата → ошибки сверху |
| `F5` | Исправить все файлы с понятными именами |
| `F6` | Пересканировать директорию |
| `F7` | Переименовать выделенный файл вручную |
| `F8` | Показать очередь файлов из Загрузок |
| `F9` | Вкл/выкл мониторинг Загрузок |
| `F10` | Настройки |
| `F11` | Очистить журнал |
| `F12` | Загрузить выделенный файл на FTP |
| `Ctrl+Z` | Отменить последнее переименование |
| `Ctrl+C` / `Ctrl+Q` | Выход |
| `Tab` / `Shift+Tab` | Переключение между панелями |
| `↑` / `↓` | Навигация по дереву |
| `←` / `→` | Свернуть / развернуть папку |
| `Enter` | Раскрыть папку / выполнить действие |

### Модалки

| Клавиша | Действие |
|---|---|
| `Enter` / `Y` | Применить |
| `N` / `Esc` | Отменить / пропустить |
| `Tab` / `↑` / `↓` | Переключение между полями (F10) |
| `Пробел` | Переключить тумблер (F10) |
| `Ctrl+T` | Транслит в поле ввода имени папки (F12) |

В русской раскладке `Y`/`N` физически печатаются как `Н`/`Т`, поэтому
подтверждение работает и в ней.

## Установка и запуск

### Что нужно

- Python **3.11** или новее.
- Терминал с поддержкой 256 цветов и мыши (xterm, kitty, alacritty,
  konsole, gnome-terminal, foot, Windows Terminal).

### Из исходников

```bash
# 1. Склонировать репозиторий
git clone https://github.com/<ваш-логин>/ok-helper-tui.git
cd ok-helper-tui

# 2. Создать виртуальное окружение
python -m venv .venv

# 3. Активировать окружение
#    Linux / macOS:
source .venv/bin/activate
#    Windows (PowerShell):
#    .venv\Scripts\Activate.ps1
#    Windows (cmd):
#    .venv\Scripts\activate.bat

# 4. Установить зависимости
pip install -r requirements.txt

# 5. Запустить
python main.py
```

Можно указать директорию сразу:

```bash
python main.py /path/to/tracks
```

Если директория не указана — берётся `root_dir` из конфига.

### Портативная версия для Windows

В разделе **Actions** на GitHub соберите workflow — в артефактах появится
готовый `.exe`:

- `ok-helper-tui-windows` → `ok-helper-tui.exe`

Скачайте файл, положите в любую папку и запустите. Python устанавливать
не нужно.

На Linux и macOS используйте запуск из исходников (см. выше).

## Настройка

Все настройки хранятся в TOML-файле:

| ОС | Путь |
|---|---|
| Linux | `~/.config/ok-helper-tui/config.toml` |
| macOS | `~/Library/Application Support/ok-helper-tui/config.toml` |
| Windows | `%APPDATA%\ok-helper-tui\config.toml` |

Первое открытие сервиса создаст файл с дефолтными значениями. Менять
настройки можно двумя способами:

1. **Из TUI** — клавиша **F10**, откроется редактор конфига.
2. **Вручную** — отредактировать TOML в любимом редакторе.

### Поля конфига

```toml
# Корневая директория, открывается при запуске.
root_dir        = '~/Tracks'

# Папка загрузок для мониторинга.
downloads_dir   = '~/Downloads'

# true — предлагать переносить новые файлы из Загрузок.
watch_downloads = false

# Тема интерфейса: auto / dark / light.
# auto — определит по переменной COLORFGBG.
theme           = 'auto'

# --- FTP ---
ftp_host        = 'ftp.example.com'
ftp_port        = 21
ftp_user        = 'username'
ftp_password    = 'secret'
ftp_path        = '/upload'

# true — режим эмуляции: подключение и чтение реальные,
# создание папок и загрузка файлов не выполняются.
ftp_readonly    = false
```

Обратите внимание: пути записаны в **одинарных** кавычках — так в TOML
не нужно удваивать обратные слэши (важно на Windows):

```toml
root_dir = 'C:\Users\you\Tracks'   # правильно
root_dir = "C:\Users\you\Tracks"   # ошибка TOML — \U не экранирован
```

## Разработка

### Запуск тестов

```bash
pip install -r requirements-dev.txt
python -m pytest -v
```

### Структура проекта

```
ok-helper-tui/
├── main.py                     # точка входа
├── config.py                   # чтение/запись конфига
├── requirements.txt
├── requirements-dev.txt
├── ok_helper/
│   ├── analyzer.py             # валидация имён файлов
│   ├── ftp.py                  # FTP-загрузка и валидация
│   ├── translit.py             # транслитерация
│   ├── theme.py                # цветовые схемы
│   ├── models.py               # модель дерева
│   ├── controls.py             # UI-контролы
│   ├── handlers.py             # watchdog
│   └── app/                    # TUI-приложение
│       ├── base.py             # состояние, журнал, фокус
│       ├── ui.py               # layout, глобальные клавиши
│       ├── nav.py              # дерево, статус-бар
│       ├── modals.py           # help / confirm / move / edit
│       ├── config_modal.py     # модалка настроек (F10)
│       ├── upload_modal.py     # модалка FTP (F12)
│       ├── actions.py          # fix, undo, open, scan
│       └── downloads.py        # мониторинг Загрузок
└── tests/
    ├── conftest.py
    ├── test_analyzer.py        # валидация имён
    └── test_ftp.py             # FTP-валидация
```

### CI/CD

На каждый push и pull request запускается workflow `.github/workflows/ci.yml`:

1. **Тесты** — pytest на Ubuntu и Windows, Python 3.11 и 3.12.
2. **Сборка** — PyInstaller `--onefile` для Windows. Собранный `.exe`
   лежит в артефактах запуска (Actions → CI → Artifacts →
   `ok-helper-tui-windows`).

Если тесты падают — сборка не запускается.
